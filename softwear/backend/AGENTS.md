# AGENTS.md — working on this Quickback project

> Generated by Quickback — regenerated on every `quickback build`. Put your
> own project-specific agent notes in a different file so they aren't overwritten.

**softwear** is a Quickback backend: you declare schema + security in TypeScript
under `quickback/`, and `quickback build` regenerates `src/`.
**Edit `quickback/`, never `src/`** — everything in `src/` is overwritten on compile.

## Golden rule — security is declarative and deny-by-default

Nothing is reachable until you explicitly allow it. Every table needs a
**firewall** (which rows a caller sees) and **access** (which roles may act).
Reach for the built-in primitive instead of hand-rolling logic in an action.

## When to use what

Before writing a custom route or action, check whether a primitive already fits:

| You want… | Reach for | Reference |
|---|---|---|
| A filtered / paginated / field-projected read | a **view** under `read.views` — not a hand-written GET | [read](https://docs.quickback.dev/compiler/definitions/read) |
| A write limited to allowed state changes (e.g. `applied → screening`) | a **transition** (a guarded `PATCH`), not a bare update | [transitions](https://docs.quickback.dev/compiler/definitions/transitions) |
| A custom endpoint / business logic | an **action** with declarative `access` (`unsafe` only as a last resort) | [actions](https://docs.quickback.dev/compiler/definitions/actions) |
| Write a parent + its owned child rows atomically (junctions, phones/emails) | a **changeset** — declare `owns` on the root, send `application/vnd.quickback.changeset+json` to its `PATCH /:id` or `POST /` — not a hand-orchestrated action | [changesets](https://docs.quickback.dev/compiler/definitions/changesets) |
| Restrict which fields a write may set | **guards** | [guards](https://docs.quickback.dev/compiler/definitions/guards) |
| Stamp a **proven caller identity** on a write (the attendee's own id) — never a client-sent value | **`q.stamp({ fromScope, claim })`** for the identity column (`q.scope` stays for the tenant column). `q.scope` tenant columns are *stamp-and-**verify*** (firewall-checked); `q.stamp` identity columns are *stamp-and-**prove*** (token provenance, **never** a firewall arm). Scope-only callers are force-stamped from the proven claim; org-admins write it via the org path | [schema → q.stamp](https://docs.quickback.dev/compiler/definitions/schema#qstamp--proven-principal-identity-columns) |
| Hide PII from some roles in responses | **masking** | [masking](https://docs.quickback.dev/compiler/definitions/masking) |
| The same who/row rule stamped on several resources | a **named gate** in `authz.rules` — bare name in `access`, `{ rule: '<name>' }` in `firewall` — before copying a firewall lane across files | [named gates](https://docs.quickback.dev/compiler/definitions/access#named-gates-authzrules) |
| Tell clients "this changed — refresh" | **named invalidations** (`invalidates:` on an action) | [named invalidations](https://docs.quickback.dev/stack/realtime/named-invalidations) |
| Fire a realtime signal after a **changeset** commits | **`afterCommit`** on the aggregate root — a declarative broadcast, NOT a hand-rolled `try{ realtime.* }catch{}` tail. Sourcing a `q.stamp` identity column (`root.<col>`) into the payload is **compile-gated**: the delivery audience must be provably ⊆ the stamping scope kind (a same-kind scope-keyed room), else it fails closed unless you set `disclosesStampedIdentity: true`. Emit is at-least-once (a keyless retry re-emits); `meta.transactional:false` is the only "row-written ⇒ event-fired" signal | [changesets → afterCommit](https://docs.quickback.dev/compiler/definitions/changesets#aftercommit--emit-a-realtime-signal-after-the-changeset-commits) |
| Re-embed or push-notify after a **changeset** commits | `afterCommit: { reindex: true }` (root's `embeddings` block required, root row only) and `afterCommit.notify` (web-push provider required; audience = a delivery profile, SAME disclosure gates as broadcast) — never a hand-rolled queue send in an action tail | [changesets → reindex/notify](https://docs.quickback.dev/compiler/definitions/changesets#reindex--re-embed-the-committed-root) |

## Access — who is calling

Uppercase names are compiler markers; lowercase are org-membership roles;
`scope:<kind>:<role>` is a scoped role (a proven relationship, e.g. an event attendee).

- `PUBLIC` — anyone, no auth. `AUTHENTICATED` — any signed-in caller: a full
  session **or** a scope-token principal (it's the wrapper). `SESSION` — a full
  session only. `SCOPED` — a scope-token principal only.
- **Reusing the same role expression in more than one place? Define it once** in
  `authz.roles` (in `quickback.config.ts`) and reference it by bare name in every
  `access: { roles: [...] }` — don't copy an inline list across files.
- Full guide: [access → pseudo-roles](https://docs.quickback.dev/compiler/definitions/access) ·
  [centrally defined access rules](https://docs.quickback.dev/compiler/definitions/access#centrally-defined-access-rules).

## Firewall — `WHERE <column> = <authorized value>`

`organization` and `owner` are the built-in tenant lanes. A **scoped role** is a
third lane on a different column: `WHERE event_id = ctx.scope.event.id`.

**Serving callers who aren't org members** (event attendees, vendors, drivers)?
Do **not** fake an active organization and do **not** use `exception: true`.
Compose **org OR scope** in an `{ any: [...] }` group so each identity is filtered
by the axis it actually has:

```ts
firewall: [{ any: [
  { field: 'organizationId', equals: 'ctx.activeOrgId' }, // org member
  { field: 'eventId',        equals: 'ctx.scope.event'  }, // scope principal
]}]
```

The compiler **fails the build** if you grant a scope caller (`SCOPED` or a
`scope:<kind>:<role>` role) on a resource whose firewall can't filter them — that
would otherwise silently return `200 + []`. Fix it with the `{ any: [...] }` arm
above, a `via:` relationship, or `firewall: [{ exception: true }]`.

**Repeating the same lanes across tables?** Don't copy them file-to-file. The
tenant lane has a named anchor — declare `authz.tenants.org` once and write
`{ tenant: 'org' }`; a whole who+row bundle becomes a **named gate** in
`authz.rules`, stamped as `firewall: [{ rule: '<name>' }]`. References
AND-compose with the resource's own lanes — they can only *narrow* row
admission, never widen it.

**Never** use `firewall: [{ exception: true }]` to route around a missing lane —
it means "no row-level access control." See
[firewall](https://docs.quickback.dev/compiler/definitions/firewall) · [scopes](https://docs.quickback.dev/compiler/definitions/scopes).

## Writes, audit fields, and which `db` you're holding

Every feature table carries compiler-managed columns: `id` (defaulted),
`createdAt`/`createdBy`/`modifiedAt`/`modifiedBy` (audit), `deletedAt`/
`deletedBy` (soft delete), and the tenant scope column(s). They are **declared
visibly** in the table — `...q.audit()` / `...q.softDelete()` spreads (or the
canonical literal lines) — and the compiler **validates them against canon**:
editing their shape, or omitting the spreads, is a compile error with a fix-it
(`quickback migrate visible-columns` adds them). Their **values** are still
compiler-owned — never set them in a write. Rules that follow from that:

- **Don't hand-stamp audit fields.** The action `db` **hard-stamps** them on
  every insert/update (and on `onConflictDoUpdate`'s conflict branch) from the
  verified caller — a value you pass is silently overwritten. Don't build
  `createdAt: new Date().toISOString()` objects: it's dead code on the wrapped
  db, and on Postgres the audit columns take `Date` objects, so the hand-built
  ISO string is also a portability trap on unwrapped handles.
- **Don't pass the scope column** (`organizationId`/`ownerId`/…) on inserts —
  the scoped `db` fills it from the verified session/scope context.
- **Soft delete** = `db.update(t).set({ deletedAt: <anything> })` — the wrapper
  normalizes the stored value to now/caller. Reads through generated routes and
  the scoped `db` already exclude soft-deleted rows.
- **Which handle:** the action's `db` is scoped (firewall WHERE + autofill +
  audit) — default to it. `unsafeDb` (on `unsafe: true` actions) skips the
  firewall but still audit-stamps. Only system-side code (seeds, migrations)
  uses the raw client, and there audit/provenance is **your** responsibility.
- Writes with no authenticated caller **throw** (fail closed) — system lanes
  stamp synthetic actors (`scope:<kind>:<subject>`, `actor:<type>:<id>`), never
  `null`.

## API contract essentials

- **Errors are RFC 9457** `application/problem+json` — switch on the `code`
  extension member (the full enum ships in `openapi.json`).
- **Retries:** send an `Idempotency-Key` header (UUID, ≤255 chars) on writes —
  replays return the cached response with `Idempotency-Replayed: true`. Claims
  are bound to the calling principal; unauthenticated callers are rejected
  unless the PUBLIC action declares `idempotency: 'dedupe'`.
- **Pagination:** prefer the opaque keyset cursors (`?starting_after=` /
  `?ending_before=` from `pagination.nextCursor`/`prevCursor`) over offsets.
  Actions that declare `pagination` answer the same `{ data, pagination }`
  envelope and read `limit` / `starting_after` / `sort` (forward only); a
  cursor they reject is a typed 400 (`PAGINATION_*`), never a restart.
- **Concurrency:** pin `If-Match` to the record's revision — the
  `updatedAt`/`modifiedAt` value as returned in the row, **not** the `ETag`
  header (that's a body hash; echoing it always 412s). Honored on changesets
  AND plain single-record `PATCH`/`PUT`/`DELETE` (same comparator;
  `PATCH`/`PUT` also pin the revision into the write — a concurrent writer
  → 412 on every provider). Mismatch → 412; no revision column, batch
  endpoints, and the POST changeset variant → 428. Never silently ignored.
- **Contract v2 only:** `?include=` embeds allowlisted FK targets
  (`?include=<fkColumn>`) AND owned child collections
  (`?include=<ownsRelation>` — the aggregate reader) into a top-level
  `included` map; the target's access/firewall/masking all apply and
  unknown `?fields=` names are a 400. Declare the allowlist with
  `read.include: ['<fkColumn> | <ownsRelation>']` (or per view).
- **Event surface:** `GET /asyncapi.json` documents realtime channels + named
  invalidation events + outbound webhooks (same auth gating as
  `/openapi.json`). See [api-contract](https://docs.quickback.dev/stack/api-contract).
